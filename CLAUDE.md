# CLAUDE.md

- The engine (`packages/engine`) is the single source of truth for rules. The web app, the
  generator and the scoring Function never re-implement scoring, locks or budgets.
- Answers are server-side only. Scoring happens in the Pages Function (`functions/api/guess.ts`)
  against the answers bundle (`functions/_puzzles.json`, generated by `npm run puzzles`,
  gitignored). The browser is served the public (answer-free) puzzle files and never receives an
  answer, so it can't be read from the page. Keep it that way: don't ship answers to the client,
  and don't commit `_puzzles.json`.
- The same handlers also run on Node for the IIS host (`server/`, bundled by `npm run build:iis`
  with the answers inlined into `dist/iis/server`, outside the served site). Keep the handlers to
  Web `Request`/`Response` so both hosts work, and keep the server bundle out of the site folder.
- Game state is the _scored_ guesses the server returned (marks per tile), keyed by entry. The
  browser can't recompute feedback without the answer, so it stores the marks; locks, budgets,
  solved state, status and the share card all derive from those. Don't store anything else.
- New rules go in `RuleSet` with a default, and puzzle files can override them. Don't hard-code
  rules in the UI.
- Every engine change gets unit tests in `packages/engine/test`.
- Test the full stack locally with `npm run preview`: the built site and the API on the Node
  server IIS runs (`server/preview.ts`). See `docs/staging.md` for previewing a branch privately.
- API features that need the database are Node-only (`server/api/`), listed in `FEATURES`
  (`server/api/features.ts`). The browser asks `/api/features` and hides what the host lacks, so
  the same build keeps working on Cloudflare Pages until the move to IIS is finished.
- The Node server keeps its own record of each player's game (`server/records.ts`): guesses,
  hints and restarts, attempt by attempt, keyed by the browser's random player id. Anything ranked
  (the leaderboard) comes from that record, worked out with the engine, never from what the
  browser says. So every hint goes through the server: the published puzzle has neither answers
  nor second clues (`hasClue2` only), and `/api/clue` sends one when the player reveals it.
- Ranked wins that look too good are flagged for review (`server/review.ts`). Flags never change
  the leaderboard on their own; an admin decides with `server/admin.ts` (`keep` or `hide`).
- Database schema changes are new entries at the end of `MIGRATIONS` (`server/db.ts`), with
  tests. Never edit or reorder one that has shipped.
- Naughty words are meant to be laughed at, never hurtful: no slurs (race, ethnicity, religion,
  sexuality, gender identity, disability), and keep insults balanced between men and women. Every
  new word needs both clues, and `npm run check:naughty` must pass.
- Name branches `feat/<topic>`. Cloudflare Pages only builds preview deployments for `feat/*`
  branches, so a branch with any other name gets no preview.
- Never commit real host names, IP addresses, domains or account names. Use `example.com`,
  `192.0.2.x` and repository variables or secrets instead.
