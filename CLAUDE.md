# CLAUDE.md

- The engine (`packages/engine`) is the single source of truth for rules. The web app, the
  generator and the scoring Function never re-implement scoring, locks or budgets.
- Answers are server-side only. Scoring happens in the Pages Function (`functions/api/guess.ts`)
  against the answers bundle (`functions/_puzzles.json`, generated by `npm run puzzles`,
  gitignored). The browser is served the public (answer-free) puzzle files and never receives an
  answer, so it can't be read from the page. Keep it that way: don't ship answers to the client,
  and don't commit `_puzzles.json`.
- Game state is the _scored_ guesses the server returned (marks per tile), keyed by entry. The
  browser can't recompute feedback without the answer, so it stores the marks; locks, budgets,
  solved state, status and the share card all derive from those. Don't store anything else.
- New rules go in `RuleSet` with a default, and puzzle files can override them. Don't hard-code
  rules in the UI.
- Every engine change gets unit tests in `packages/engine/test`.
- Test the full stack (static site + Function) locally with `npm run preview` (Wrangler). See
  `docs/staging.md` for previewing a branch privately.
- Never commit real host names, IP addresses, domains or account names. Use `example.com`,
  `192.0.2.x` and repository variables or secrets instead.
