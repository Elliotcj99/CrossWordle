# Scoring Function

A Cloudflare Pages Function that scores guesses on the server, so puzzle answers never reach the
browser.

## How it works

- `api/guess.ts` handles `POST /api/guess` with `{ puzzleId, entryId, guess }` and replies with the
  tile marks for that one guess (`{ letters, solved }`). It uses the engine's `evaluateGuess`, so
  scoring is identical to everywhere else.
- `_puzzles.json` is the answers bundle: every puzzle in full, keyed by id. It is generated by
  `npm run puzzles` (the `--answers-out` target) and **gitignored** — it holds the plain answers, so
  it must never be committed to a public repo. The build regenerates it, and it is compiled into the
  Function; Function code is not downloadable, so the answers stay on the server.

Files and folders under `functions/` whose names start with `_` are not routed, so `_puzzles.json`
is never served as a static asset. (The static site is served from `apps/web/dist`; `functions/`
is compiled into the Worker, separately.)

## Deliberately stateless

The endpoint keeps no per-player state. It only reports how one guess scored, so the browser still
owns the guess budget, the win/lose state and the "real word" check. That means a determined caller
can score arbitrary guesses against an entry — the same as any Wordle — but can't read the answers
outright. Rate limiting can be added later if abuse is a concern.

## Caveat: the answers must come from a private source

Hiding answers from the page only hides them from players if the answers aren't public elsewhere.
The plain puzzle sources live in `puzzles/*.json`; if those are committed to a **public** repo, the
answers are readable on the repo host regardless of this Function. See `docs/staging.md` and the
project notes for the repo/deploy arrangement that keeps the answer source private.

## Testing locally

`npm run preview` builds the site and runs it with the Function under Wrangler
(`wrangler pages dev apps/web/dist`), at <http://127.0.0.1:8788>.
